# UI-1 Catalog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the seven fee-catalog admin screens per `docs/api-contracts/UI-1-SPEC.md` (approved) — the first phase of the BILL-ADMIN-UI arc.

**Architecture:** One new tabbed page (`/finance/bill/catalog`) under a new top-level "Billing" nav section. Six tabs reuse a promoted `ConfigSection`/`ConfigRow` inline-CRUD component (extracted from `hr/setup/page.tsx`, behavior-preserving). The seventh (Fee Structures) is a `DataTable` + `Dialog`-based form with `useFieldArray`, mirroring the old rail's own `fee-structure-form.tsx`. All backend endpoints already exist and are unchanged by this phase.

**Tech Stack:** Next.js 14 App Router, shadcn/ui, TanStack Query, React Hook Form + Zod (Fee Structures dialog only), axios, vitest + @testing-library/react (jsdom).

## Global Constraints

- Money values sent to `bill_*` endpoints are decimal strings, 2dp (`@IsMoneyString()` on the backend) — convert at the API-call boundary only, matching Money's own `toDb()` discipline; RHF/local state keeps plain numbers for input UX.
- BS date fields use `<BsDateInput>` — never a raw HTML date input — for every `effectiveFrom`/`effectiveTo` field.
- Roles: ACCOUNTANT_AND_ABOVE (`PLATFORM_ADMIN`, `SCHOOL_OWNER`, `PRINCIPAL`, `ACADEMIC_COORDINATOR`, `ACCOUNTANT`) read/write; `OWNER_ONLY` (`PLATFORM_ADMIN`, `SCHOOL_OWNER`) delete — delete actions hidden client-side for non-owner viewers, in addition to the backend's own 403.
- Never pair `bg-white` with `dark:bg-boxdark` on the same element (the known, logged, unfixed dark-mode bug — see `FIX-DARKMODE-CONTRAST` in `BILL-BUGS.md`).
- New nav: a top-level **"Billing"** sidebar section (Srijan's ruling — not nested under the old "Finance" dropdown). Route: `/finance/bill/catalog`.
- Never self-schedule (agent). Servers stopped cleanly by their own PID when done — do not leave a dev server running for Srijan; he'll run his own to eyeball it.

import type {
  ApiResponse, PaginatedResponse,
  FeeHead, CreateFeeHeadData, UpdateFeeHeadData,
  DiscountReason, CreateDiscountReasonData, UpdateDiscountReasonData,
  CorrectionReason, CreateCorrectionReasonData, UpdateCorrectionReasonData,
  TransportRoute, CreateTransportRouteData, UpdateTransportRouteData,
  TaxRate, CreateTaxRateData, UpdateTaxRateData,
  LateFeeRule, CreateLateFeeRuleData, UpdateLateFeeRuleData,
  BillFeeStructure, CreateBillFeeStructureData, UpdateBillFeeStructureItemsData,

export const billCatalogApi = {
  feeHeads: {
    list: () => api.get<ApiResponse<PaginatedResponse<FeeHead>>>('/finance/fee-heads', { params: { limit: 100 } }),
    create: (data: CreateFeeHeadData) => api.post<ApiResponse<FeeHead>>('/finance/fee-heads', data),
    update: (id: string, data: UpdateFeeHeadData) => api.patch<ApiResponse<FeeHead>>(`/finance/fee-heads/${id}`, data),
